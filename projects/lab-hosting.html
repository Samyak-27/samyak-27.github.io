Software infrastructure

Local hosting for lab software

I moved lab software and its document archive to a Windows OptiPlex and verified that researchers could reach the database and PDFs after the host rebooted.

Organization
UC Pavement Research Center
Host and access
Windows OptiPlex, Caddy, Cloudflare Tunnel, OpenSSH
Operations
PowerShell, SQLite, SQL and CSV exports

Moving the services to Windows

I moved the lab application services to an OptiPlex. I configured Caddy and Cloudflare Tunnel for application access, set up OpenSSH administration, and used PowerShell to automate startup and make service status and logs available during troubleshooting.

Making the archive recoverable

I organized local equipment and document records in SQLite and prepared SQL and CSV exports. I checked backup restoration as well as day-to-day access, so I could verify that the archive was recoverable if the host needed to be rebuilt.

Verifying access after a reboot

I tested database and PDF access after restarting the services, then repeated the checks after a full PC reboot. The second test verified that Windows brought the services back automatically.

Providing a fallback for local AI

I connected a local Ollama service to LabOps through an authenticated proxy. The model could take time to respond while warming up on CPU hardware, so I retained a parser fallback for request lookups and draft creation.
